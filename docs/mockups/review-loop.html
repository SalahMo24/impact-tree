What each piece is, and what is behind it

  1. View title. R4's toggles plus two: a third filter, "Unresolved threads" (Q7), and "Submit review…". Both are view/title commands.
  2. Summary line. TreeView.message gains the unresolved thread count and your pending comments.
  3. File rows. 💬 counts the unresolved threads in the file. 👁 is GitHub's per-file "viewed" state, read from viewerViewedState and written with markFileAsViewed / unmarkFileAsViewed when the file's checkbox changes (proposal a). "Changed since viewed" is GitHub's DISMISSED state (Q5). A failed write shows on the row with a retry.
  4. Change rows. 💬 counts the unresolved threads whose line falls inside the change; ✎ counts your pending comments there.
  5. Threads in the diff. A CommentController on the review diff, the same widget the GitHub Pull Requests extension uses. commentingRangeProvider allows only lines GitHub accepts: lines in the diff's hunks, on either side. The buttons are comments/commentThread/context menu commands. Hover a line and click + to try it.
  6. Details panel. R5's panel gains a Threads section for the shown change or file, including outdated threads and file-level comments, which have no place in the diff. "Comment on this change" and "Comment about this caller" start a thread on the change's first line (Q6).
  7. Status bar. A second StatusBarItem: your pending comments and "Submit review…".
  8. Submit. Depends on the "Submit" switch at the top (Q1). github.com style: a "Review changes" button in the diff's title bar (editor/title) opens "Finish your review". VS Code has no popovers, so the real one is a small webview the button opens; the mockup draws it where github.com does. PR extension style: an editor tab with the PR's description, timeline and a comment box whose buttons are the review events. Details panel: the Details panel switches to the form. It lists your pending comments, takes the summary and the event (COMMENT, APPROVE, REQUEST_CHANGES), and warns before approving with work left (Q3). Sent with submitPullRequestReview; the pending review itself is GitHub's draft review (addPullRequestReview, addPullRequestReviewThread).
  9. Notification. window.showInformationMessage after a submit, or showErrorMessage with "Retry" when GitHub refuses. A failed call never drops your text: the draft stays where it was.
  10. Progress meter. TreeView.message is plain text: it cannot draw a bar, colour or a link. The meter goes at the top of the Details webview instead, which already repaints on every tick. Switch "Tree" to "Today" to compare.
